## 2. AI-стек

### Локальные инструменты (бесплатно)

```bash
# Извлечение текстового слоя из PDF (Archicad сохраняет размеры как текст!)
pdftotext "НОВОЕ ОЧАКОВО (2).pdf" output.txt

# Извлечение страницы как изображения
pdftoppm -jpeg -r 250 -f НОМЕР_СТРАНИЦЫ -l НОМЕР_СТРАНИЦЫ "НОВОЕ ОЧАКОВО (2).pdf" page

# Список всех изображений в PDF
pdfimages -list "НОВОЕ ОЧАКОВО (2).pdf"

# Метаданные PDF
pdfinfo "НОВОЕ ОЧАКОВО (2).pdf"
```

### Vision API через OpenRouter (платно, ~$0.008/анализ)

```bash
# В репозитории v0-test-api лежит скрипт:
node ~/IdeaProjects/v0-test-api/scripts/vision.js \
  --image page.jpg \
  --model google/gemini-2.5-flash \
  --max-tokens 3000 \
  --prompt "Твой промпт здесь"
```

**Модели (через OpenRouter):**
| Модель | Цена (вход/выход за 1M tok) | Когда использовать |
|--------|-----|------|
| `google/gemini-2.5-flash` | $0.15/$0.60 | Ежедневные проверки (дефолт) |
| `google/gemini-2.5-pro` | $1.25/$10 | Бесплатный тир 50 запросов/день |
| `openai/gpt-4o` | $2.50/$10 | Сложный пространственный анализ |
| `anthropic/claude-sonnet-4` | $3/$15 | Финальная валидация |

**Ключ OpenRouter:** лежит в `~/.claude/settings.local.json` → `OPENROUTER_API_KEY`
**Баланс:** ~$4, автопополнение. Одного анализа хватает на ~470 запросов Gemini Flash.

### Две стратегии анализа

1. **pdftotext** — дёшево, даёт точные цифры и спецификации. Использовать для: размеров, высот, примечаний, ведомостей.
2. **Vision API** — платно, даёт пространственное понимание. Использовать для: планировки, развёрток, проверки стыков между листами.

**Правило:** сначала pdftotext → если данных не хватает для ответа → Vision API.

## 3. Роль AI-надзорщика

### Что проверять (приоритеты)

**P0 — Безопасность и коммуникации (нельзя ошибиться):**
- Вентиляция: вытяжки в санузле и кухне, приток воздуха
- Электрика: нагрузка на щит, 380V для варочной, розетки во влажных зонах
- Сантехника: уклоны, доступ к стоякам, гидроизоляция
- Тёплый пол: стык с остальным полом, терморегулятор
- Кондиционеры: вывод дренажа, внешние блоки

**P1 — Функциональность (будет бесить если не сделать):**
- Розетки: достаточно ли, в нужных ли местах
- Освещение: сценарии, выключатели по пути движения
- Хранение: шкафы, гардеробные
- Кухня: рабочий треугольник, техника
- Санузел: эргономика, душевой подиум

**P2 — Комфорт и вайб (то ради чего ремонт):**
- Звукоизоляция
- Сценарии освещения (диммеры, тёплый/холодный свет)
- Визуальные стыки материалов
- Ниши для штор (уже в проекте — хорошо)
- Микроклимат

### Методология проверки

Каждый лист проекта → три вопроса:
1. Что здесь не так с точки зрения строительных норм?
2. Что будет неудобно в реальной жизни?
3. Что упущено / не указано?

Затем → перекрёстная проверка листов между собой:
- План мебели vs План электрики (розетки там где техника?)
- План сантехники vs План монтажа (выводы совпадают с конструкциями?)
- План потолка vs План освещения (светильники совпадают?)
- План демонтажа vs План монтажа (логика перепланировки?)

## 4. Что уже известно о проекте

### Плюсы (что сделано хорошо)
- Детальный проект: 18 технических листов
- Скрытые двери Invisible Doors — эстетично
- Ниши для штор предусмотрены в конструкции потолка

- Развёртки всех стен с привязкой размеров
- Указаны марки материалов (плитка, ламинат)

### Потенциальные проблемы (первый взгляд)
- Очень сложная геометрия коридора — много углов и выступов
- Санузел маленький (~5 м²) при насыщенном наполнении
- Выступ стояка канализации 385×310 мм — мешает планировке санузла
- 2 кондиционера в квартире 42.7 м² — может быть избыточно
- Нет информации о шумоизоляции
- Нет информации о вентиляции (только «ОВ» на плане)

### Вопросы к дизайнеру (накопительно)
- Где вентиляционные каналы и вытяжки?
- Как организован приток воздуха?
- Из чего сделаны стены (материал несущих и перегородок)?
- Кто такой заказчик Соболева — это предыдущий проект или текущий владелец?

## 5. Правила работы AI в этом проекте

1. **Сначала данные, потом выводы.** Не гадать — всегда проверять через pdftotext или vision.
2. **Объяснять клиенту на человеческом.** Эдди — не строитель. Каждая проблема должна быть объяснена: что не так → почему это важно → как исправить → сколько примерно стоит.
3. **Приоритеты.** P0 (безопасность) > P1 (функциональность) > P2 (вайб). Бюджет малый — предлагать эконом-решения.
4. **Фиксировать всё.** Каждый вывод — в SESSION_LOG.md. Каждое решение — с датой и обоснованием.
5. **Перекрёстная сверка.** Листы проекта могут противоречить друг другу. Всегда проверять стыки.
