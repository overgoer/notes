## Найденные расхождения

### 1. PATCH /users — полный апдейт (заметно)
- **Дока:** «Метод PATCH реализован как полный апдейт: в теле запроса обязательно указывать оба поля — name и age»
- **v2 сейчас:** принимает частичный апдейт (одно поле — второе берётся из текущей записи)
- **Фикс:** требовать оба поля → 400, если чего-то нет
!! в доке опишем что можно обновлять поля частично и это не обнуляет другие поля. важно чтобы на версии 1 работало иначе и баги сохранились. с докой аккуратно не укапывайся в формитирвоание и не порти имеющееся. филиграмно

### 2. DELETE /users — объект в ответе (заметно)
- **Дока:** `{ "message": "User deleted successfully", "user": { id, name, age, status } }`
- **v2 сейчас:** только `{ message }`
- **Фикс:** добавить удалённого пользователя в тело ответа !! да делаем фикс

### 3. pass_code авто-пропуска — 8 hex (заметно)
- **Дока:** формат `SCR-` + 8 hex-символов
- **v2 сейчас:** `randomBytes(3)` = 6 hex (`SCR-XXXXXX`); при этом POST /passes отдаёт 8 hex — внутренняя несогласованность
- **Фикс:** `randomBytes(4)` в v2/users.js:84 !! делаем фикс только в вессии 2 конечно же

### 4. Cache-Control — no-cache (заметно)
- **Дока:** `Cache-Control: no-cache` на каждом ответе
- **Факт:** общий middleware ставит на GET `public, max-age=30`
- **⚠️ Нюанс:** middleware общий для v1/v2, а в v1 кашевое поведение — учебный баг (не трогать!)
- **Фикс-предложение:** не менять middleware — v2-роуты сами выставляют `Cache-Control: no-cache` в ответах. !! если сработает - делаем фикс

### 5. Косметика сообщений (косметика)
- PATCH: дока «Age must be an integer» / «Valid name is required» → v2 сейчас «Valid age is required» / «Invalid name format» !! посмотри где логичне в доке что то поменять - предложи
- POST: дока «Valid name is required» (и при отсутствии, и при неверном формате) → v2 сейчас «Name and age are required» / «Invalid name format…»
- 401 без ключа: дока «Invalid API key» → v2 сейчас «API key is required in X-Fix-Bug header»
