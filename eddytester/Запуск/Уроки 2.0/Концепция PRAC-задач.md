# Концепция PRAC-задач — самостоятельная практика по методам

> Решение 2026-08-21: детективная тема отменена. Вместо неё — задачи в стиле Jira: **задача разработки, дошедшая до тестирования** (как в реальных проектах).
> Статус: концепция на согласование. Реализация после ревью прототипа одной задачи.

---

## Идея

- Страница метода = карточка задачи разработчика, переведённой на тестирование. Студент — тестировщик, которому задачу назначили.
- Описание пишется от лица разработчика: что реализовано, что должно работать, «проверь, пожалуйста».
- Под описанием — тест по методу: чекбоксы «Найденные баги» (существующая механика renderTest + LESSONS_CONFIG).
- Без игры, без детектива, без канбана — строгая рабочая карточка.

## Поля задачи

1. **Ключ + заголовок** — «PRAC-9 · Реализовать метод GET /users» (задача разработки, не «протестируй»)
2. **Приоритет** — метка (Высокий/Средний)
3. **Статус-плашка** — авто, см. ниже
4. **Описание** — 2–3 фразы от лица разработчика: что сделано, где смотреть, что проверить
5. **Ожидаемое поведение** — ссылка на конкретный метод в документации (Google Docs, якорь на заголовок раздела: `…/edit#heading=h.xxx`)
6. **Среда** — URL эндпоинта + ссылка на коллекцию v1
7. **Эталон** — ссылка на коллекцию/метод V2
8. **Сдача** — mailto для баг-репортов (опционально Telegram). Баг-репорты НЕ публикуются под задачей — только на почту
9. **Тест** — существующий renderTest (чекбоксы багов, «Проверить», «Сбросить»)

## Статус-плашка (авто, просто и надёжно)

- Данные уже есть: progress каждого урока (completed, attempts) грузится в loadProgress — бэк трогать не нужно.
- Логика: нет прогресса → **«На тестировании»** (серая); есть попытки, тест не пройден → **«В работе»** (жёлтая); completed → **«Готово»** (зелёная).
- Ставится автоматически по результату теста; «Пройти заново» → возврат в «В работе».
- Ручной смены статуса нет — проще и честнее.
- Если усложнится — выпиливаем плашку, остальное не страдает.

## Чего НЕ делаем

- Канбан, drag&drop, колонки, аватары исполнителей
- Комментарии/вложения под задачей: баг-репорты студент шлёт на почту (или в Telegram), под задачей их не храним
- Прогресс — ТОЛЬКО галочки и пройден/не пройден тест; никаких артефактов в системе
- Игровые/детективные обёртки
- Ссылку на /bugs внутри задачи (это готовые ответы)
- Правки бэка: LESSONS_CONFIG для 5 методов уже содержит баги, correct[] и дистракторы
