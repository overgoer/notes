## Суть гипотезы

**Не заменять видео, а сделать страницу урока самой игрой.** У нас есть движок, которого нет ни у одного конкурента — автоматическая сверка найденных багов с эталоном на сервере. Это и есть вау-мотор. Видео для него — не обязательное топливо.

Студент не «досматривает урок», а **раскрывает дело**: читает брифинг → изучает досье → идёт по уликам-подсказкам → предъявляет улики (чекбоксы) → сервер выносит вердикт → пишет рапорт.

## На каких механиках держится (без нового кода)

- `LESSON_MAP` + `<div class="test-section">` — движок сам рендерит чекбокс-лист
- `LESSONS_CONFIG` в `progress.js` — варианты, правильные ответы, порог прохождения, попытки
- Существующие блоки урока: lesson-desc (брифинг), Материалы (досье), Задание (рапорт-артефакты), details-блоки (улики-подсказки) — всё это контент, не код
- Прогресс-бар в сайдбаре + подсветка «нашёл/пропустил»

## Формат урока (5 блоков)

1. **Брифинг** (lesson-desc) — 5-8 предложений детективного сюжета
2. **Досье** (Материалы) — спека эндпоинта, коллекция Postman, **V2 как «свидетель»**
3. **Улики** — раскрывающиеся подсказки «Куда смотреть?» (details-блоки)
4. **Предъяви улики** (test-section) — чекбоксы с багами-подозреваемыми + ловушки → вердикт сервера
5. **Рапорт** — что нашёл / что пропустил, попытки, артефакты для ментора

## Почему это вау

- Единственное место, где твои «находки» сверяют с эталоном и выносят вердикт
- Сюжетная арка: Дело №1 (часть багов мелькала в уроках 1-8 — подтверди сам) → Дело №4 (полный экзамен, кульминация «API соврал, а база данных — нет»)
- V2 как свидетель и БД как место преступления — инструменты, которых нет в других курсах

## Чего НЕ делаем (чтобы не опустить продукт)

- Никаких очков, гейтинга, сложной логики — только существующие LESSON_MAP / LESSONS_CONFIG / renderTest
- Никаких изменений формата страницы — только контент в существующих блоках

## Компромисс по видео

- Урок 9 — видео-инструктаж (5-7 мин), уже в плане
- Опционально: видео-брифинг Эдди 2-3 мин на каждое дело (вступление в сюжет, личность сохраняется)
- Страница работает и без видео — запуск не блокируется съёмкой

# Образец: Дело №1 «Первые подозреваемые» (GET /users + GET /users/{id})

## 1. Брифинг (lesson-desc)

> Детектив, твоё первое самостоятельное дело. В отделе говорят, что база подозреваемых — `GET /v1/api/users` — ведёт себя странно: отвечает не тем, чем кажется, и не тому, кому надо. Кто-то настраивал её в пятницу вечером. Часть странностей ты уже видел краем глаза на экране в прошлых уроках — теперь твоя задача подтвердить их как улики, а не «показалось». Но есть и то, что никто ещё не находил. Поговаривают, некоторые данные вообще невозможно достать, а система безопасности дырявая, как решето.
>
> Твои инструменты: спецификация (досье), свидетель V2, который всегда говорит правду, и база данных — она не умеет врать.
>
> **Закрой дело: найди улики, предъяви их системе и получи вердикт.**

## 2. Досье (блок «Материалы»)

- **Спецификация эндпоинта:** Swagger — https://practicum.eddytester.com/swagger.html (GET /v1/api/users, GET /v1/api/users/{id})
- **Коллекция Postman:** v1-коллекция (уже импортировал в уроке 2)
- **Свидетель V2:** тот же запрос к `GET /v2/api/users` — эталон, с которым сверяем показания v1
- **Шаблон баг-репорта:** [ссылка на Google Doc]
- **Шпаргалка по багам:** https://eddytester.com/bugs (открывай ПОСЛЕ расследования, не до!)

## 3. Улики (раскрывающиеся подсказки)

**🕵️ Куда смотреть: заголовки ответа**
> В Postman вкладка Headers — не тело! Сравни заголовки ответа v1 и v2: Content-Type, заголовки безопасности, кэширование. Что из этого не должно попадать в чужие руки?

**🕵️ Куда смотреть: фильтр ?status=**
> Попробуй разные написания статуса: строчными, ЗАГЛАВНЫМИ, несуществующее значение, два значения через запятую, и… пустое значение. Как должен вести себя API по спецификации и как ведёт себя на самом деле?

**🕵️ Куда смотреть: id**
> Запроси пользователя по id. Потом запроси id, которого точно нет в базе. А теперь попробуй вместо числа подставить слово. Сколько разных «сюрпризов» в одном эндпоинте?

**🕵️ Свидетель: V2**
> Для каждого подозрительного ответа v1 сделай ТОТ ЖЕ запрос к /v2/api/users. V2 — эталон. Если ответы различаются — ты нашёл улику.

**🕵️ Место преступления: база данных**
> Открой DBeaver (креды — в /v1/api/credentials). Сравни то, что отдаёт API, с тем, что реально лежит в таблице users. API может приукрашивать.
