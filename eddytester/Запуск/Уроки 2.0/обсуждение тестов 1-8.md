## Урок 3. Что такое API — `what-is-api` — 📝 на обсуждение

> Проверка по транскрипту: видео двухчастное — теория API (расшифровка Application Programming Interface, клиент→сервер, документация как контракт) + практика (первый баг: цифра в имени принята, 201 Created). Тема «Что такое API» в видео раскрыта.

**Вопрос:** Что мы узнали об API в этом уроке?

- [x] api_abbreviation — API расшифровывается как Application Programming Interface — прикладной программный интерфейс
- [x] programs_communicate — «Программный» значит, что программы общаются между собой: клиент (Postman) отправляет запросы, сервер проверяет их и обращается к базе данных
- [x] docs_contract — Документация — это контракт API: в ней перечислены допустимые запросы, параметры и ожидаемые коды ответов
- [x] first_bug_digit — API принял имя с цифрой и вернул 201 Created, хотя документация допускает только латиницу, пробелы и тире — это наш первый найденный баг
- [ ] interface_visual_only — Интерфейс — это всегда визуальное оформление: кнопки и дизайн приложения

**successMsg:** «Отлично! Ты разобрался, что такое API, и нашёл свой первый баг. В следующем уроке оформим его в баг-репорт!»
**hintMsg:** «Вспомни расшифровку API, кто кому отправляет запросы, что такое документация — и чем закончился запрос с цифрой в имени.»

## Урок 5. Граничные значения — `boundary-values` — 📝 на обсуждение

> Проверка по транскрипту: тема совпадает (классы эквивалентности + границы на примере возраста 17/18/65/66, практика на V2).

**Вопрос:** Как правильно тестировать возраст кандидата по методике из урока (отметь всё верное)?

- [x] boundary_check — обязательно проверять значения на стыках классов, например 65 и 66
- [x] one_per_class — внутри одного класса достаточно одного значения
- [x] negative_class — В документации могут быть не все классы эквивалентности, некоторые могут только подразумеваться (например - класс отрицательных значений)
- [ ] all_numbers — Нужно проверить каждое число от 0 до 100, даже если они внутри одного класса эквивалентности
- [ ] skip_borders — 17 и 66 можно не проверять в нашем API

**successMsg:** Классно! Классы эквивалентности и границы — фундамент тест-дизайна. Теперь ты знаешь, где разработчики ошибаются чаще всего.
**hintMsg:** Вспомни разбор возраста: 17/18 и 65/66 — границы и проверяются обязательно. Внутри класса — одна проверка. Отрицательные значения документация не учла — добавили мы.

## Урок 7. База данных — `database` — 📝 на обсуждение

> Проверка по транскрипту: тема совпадает — доступ к тестовой БД через DBeaver: креды из Postman, две вкладки (Main + SSH), доверие БД > ответу API.

**Вопрос:** Что из перечисленного показано в уроке о работе с базой данных?

- [x] db_trust — Данным в базе мы доверяем больше, чем ответу API: в БД данные просто сохранены, а в API они проходят через логику разработчика, которая может их исказить
- [x] db_creds — Креды для подключения берутся из Postman: коллекция candidate API v1 → папка utility → метод GET credentials
- [x] db_tabs — Для подключения нужно заполнить две вкладки: Main (host, port, database) и SSH-туннель с паролем
- [ ] db_pro — Нужна платная версия DBeaver Pro, Community-версия не подходит
- [ ] db_old — Подключаемся через тип «PostgreSQL old»

**successMsg:** «Отлично! База данных — твой второй источник правды: теперь ты можешь проверять API на глубоком уровне.»

## Урок 8. CRUD — `crud` — 📝 на обсуждение

> Проверка по транскрипту: тема совпадает — CRUD + CRUD-L, параметры vs часть пути (200 vs 404), soft delete и каскадное удаление.

**Вопрос:** Что из перечисленного соответствует уроку про CRUD?

- [x] crud_letters — CRUD = Create, Read, Update, Delete, а в варианте CRUD-L буква L означает List: списков в БД в готовом виде нет, их создаёт API
- [x] crud_404 — Пустой список по параметру — валидный ответ 200, а запрос несуществующего ресурса по части пути — ошибка 404
- [x] crud_soft — DELETE не всегда физически удаляет: ресурс может просто помечаться удалённым и не выдаваться в GET;
- [x] повторное удаление даёт 404
- [ ] crud_put — PATCH обновляет ресурс полностью, заменяя все поля
- [ ] crud_200 — Запрос несуществующего кандидата по ID должен возвращать 200

**successMsg:** «Отлично! CRUD и разбор методов — фундамент тест-плана для любого API.»
**hintMsg:** «Вспомни расшифровку CRUD, букву L, разницу параметра и части пути, а также статус-коды для пустого списка и несуществующего ресурса.»
